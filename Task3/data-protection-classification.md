#### **1. Классификация данных**  
Для эффективной защиты необходимо определить категории данных по:  
- **Состоянию**: данные в хранилище (at rest), в передаче (in transit), в обработке (in use).  
- **Чувствительности**: персональные данные (ПДн), медицинские данные, финансовая информация, служебные данные.  
- **Профилю риска**: высокий, средний, низкий (на основе потенциального ущерба при утечке).  

| **Категория данных**                    | **Примеры**                              | **Чувствительность** | **Профиль риска** | **Состояние**       |     |
| --------------------------------------- | ---------------------------------------- | -------------------- | ----------------- | ------------------- | --- |
| **Персональные данные (ПДн)**           | ФИО, телефон, email, паспортные данные   | Высокая              | Высокий           | At rest, in transit |     |
| **Медицинские данные**                  | Диагнозы, истории болезней, анализы      | Критическая          | Высокий           | At rest, in use     |     |
| **Финансовые данные**                   | Платежи, реквизиты, бухгалтерские отчёты | Высокая              | Высокий           | At rest, in transit |     |
| **Учётные записи сотрудников**          | Логины, пароли, роли доступа             | Средняя              | Средний           | At rest, in transit |     |
| **Товарно-материальные ценности (ТМЦ)** | Оборудование, лекарства, закупки         | Низкая               | Низкий            | At rest             |     |
| **Аналитические данные**                | Статистика посещений, ABC-анализ         | Средняя              | Средний           | At rest, in use     |     |

#### **2. Обоснование необходимости защиты**  

| **Тип данных**              | **Риски без защиты**                          | **Требования регуляторов** |  
|----------------------------|----------------------------------------------|----------------------------|  
| **ПДн и медицинские данные** | Утечки → штрафы, репутационный ущерб, судебные иски | 152-ФЗ, GDPR, HIPAA (если есть иностранные пациенты) |  
| **Финансовые данные**       | Мошенничество, блокировка счетов             | PCI DSS, 115-ФЗ (противодействие отмыванию) |  
| **Учётные записи**          | Несанкционированный доступ к медкартам       | Требования ФСТЭК, ФСБ (для госучреждений) |  
| **ТМЦ**                     | Кражи, неучтённые списания                   | Внутренние политики компании |  
| **Аналитика**               | Деанонимизация, утечка косвенных ПДн         | Внутренние compliance-политики |

#### **3. Инструменты защиты данных**  

| **Тип данных**        | **Методы защиты (At Rest)**                      | **Методы защиты (In Transit)**         | **Контроль доступа**                  | **Мониторинг и аудит**                      |
| --------------------- | ------------------------------------------------ | -------------------------------------- | ------------------------------------- | ------------------------------------------- |
| **ПДн и мед. данные** | Шифрование (AES-256), DLP-системы                | TLS 1.3, VPN для филиалов              | RBAC + ABAC (Keycloak, Apache Ranger) | SIEM (Splunk, Wazuh), аудит логов (ELK)     |
| **Финансовые данные** | Tokenization (Vault), HSM-модули                 | PCI DSS-совместимые платёжные шлюзы    | MFA (Duo, Google Authenticator)       | Fraud-мониторинг (IBM Safer Payments)       |
| **Учётные записи**    | Хэширование паролей (bcrypt)                     | SSH с ключами вместо паролей           | Just-in-Time доступ (Teleport)        | Аудит сессий (Grafana, Kibana)              |
| **ТМЦ**               | Цифровые подписи документов                      | API с OAuth 2.0 для 1С                 | Ролевая модель в 1С                   | Логирование изменений в БД                  |
| **Аналитика**         | Анонимизация (k-anonymity, differential privacy) | Защищённые каналы (Apache Kafka с TLS) | Динамическое маскирование (Delphix)   | Контроль доступа к датасетам (Apache Atlas) |

#### **4. Автоматизированный контроль**  
- **DLP (Data Loss Prevention)**:  
  - **Symantec DLP** или **Digital Guardian** для блокировки передачи ПДн вне системы.  
- **Управление ключами шифрования**:  
  - **HashiCorp Vault** или **AWS KMS** для ротации и хранения ключей.  
- **Аудит действий**:  
  - **ELK-стек** (Elasticsearch + Kibana) для анализа логов.  
  - **Apache Atlas** для отслеживания lineage данных (кто и когда обращался к информации).

### **Итоговая архитектура защиты данных**  
1. **Шифрование на всех этапах**:  
   - **At rest**: AES-256 для БД (Postgres), шифрование файлов (VeraCrypt).  
   - **In transit**: TLS 1.3 для веб-портала, VPN для связи между филиалами.  
2. **Строгий контроль доступа**:  
   - Медики видят только своих пациентов, бухгалтеры — только финансовые данные.  
3. **Аудит и прозрачность**:  
   - Пациент может запросить отчёт о доступе к своим данным через **Patient Portal**.  
4. **Автоматизация compliance**:  
   - Интеграция **Apache Atlas** с регуляторными требованиями для автоматических проверок.  

Эта стратегия обеспечит защиту при 5-кратном росте нагрузки и соответствует принципам **Privacy by Design**.
